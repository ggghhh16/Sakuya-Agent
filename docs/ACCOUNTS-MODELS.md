# 账号、工作模式与多供应商配置

最新界面与上下文容量设置见 [UI-V3.md](UI-V3.md)。

新版交互、用户名迁移与权限模式详见 [工作界面更新](WORKSPACE-V2.md)。

## 首次启用

应用仍是本机服务，监听 `127.0.0.1`。新增账号并不等于已部署为公网客服平台；不同账号必须连接同一后端，才能共享工单。公开注册始终创建普通用户，首个注册者也不会自动成为管理员。

1. 参考根目录 `.env.example`，把以下项目填入 `.env`，不要提交或分享密钥：
   - `TURNSTILE_SITE_KEY`、`TURNSTILE_SECRET_KEY`、`TURNSTILE_HOSTNAMES`。
   - `SMTP_HOST`、`SMTP_PORT`、`SMTP_SECURITY`、`SMTP_FROM`、`SMTP_USERNAME`、`SMTP_PASSWORD`。
2. 在 Cloudflare Turnstile 控制台允许实际访问域名。前后端都需要能够访问 Cloudflare；必须使用实际密钥。生产程序没有跳过验证码的选项。
3. SMTP 支持 `starttls`（默认 587）或 `ssl`（默认 465），证书验证始终开启；按邮件服务要求使用授权码。
4. 创建管理员，在项目目录执行：

   ```powershell
   .\scripts\setup-admin.ps1 -Email '你的邮箱地址'
   ```

   新账号会要求交互输入两次密码；已有账号会被提升为管理员。这个本机命令是管理员初始化入口，不存在注册管理员的网络接口。复制整个打包应用到其他电脑时，可在设置 `SAKUYA_DATA_DIR` 为实际数据目录后执行 `resources/backend/sakuya-service.exe --admin-email '你的邮箱地址'`。
5. 从托盘退出旧版 Sakuya 后，使用根目录快捷方式重新打开。新版本要求服务协议 6，拒绝复用缺少普通账号工作区隔离的旧后端。

未配置 Turnstile 时无法登录；未配置 SMTP 时无法公开注册。不会显示假验证码，也不会把验证码返回给浏览器或写入日志。

## 注册、登录与工单

- 注册：填写用户名、邮箱及密码 → 完成人机验证 → 发送邮箱验证码 → 填写 6 位验证码 → 注册 → 登录。
- 密码要求：8–128 位，至少一个 ASCII 大写字母和一个小写字母；前后端都会校验。密码使用随机盐和 scrypt 存储。
- 邮箱验证码有效期 10 分钟，最多尝试 5 次，成功后销毁；同邮箱 90 秒内不能重复发送，另有来源地址限流。
- 人机验证由后端调用 Turnstile Siteverify，并核对 action 和 hostname。登录同样需要人机验证。
- 会话为随机令牌，数据库只保存摘要。勾选「记住下次登录」时保留 30 天；未勾选时为浏览器临时 Cookie，后端最多保留 24 小时。密码不保存到浏览器存储。Cookie 使用 HttpOnly、SameSite=Lax（兼容既有日历 OAuth 回调）；所有写操作仍检查来源和自定义请求头。退出后服务端撤销当前会话。
- 普通用户：默认进入工作首页，可使用对话和工作功能（任务、日历、研究、诊断）和个人模型设置；工单仅可查看自己的、提交、编辑标题和描述、查看公开回复。不能修改工单状态、优先级或负责人，不能回复工单，不能查看内部备注及他人工单。
- 管理员：查看全部工单、接受并分配给自己、修改状态及优先级、回复用户、保存内部备注，以及使用聊天、研究、规划和设置。
- 管理员公开回复发送到工单页面，用户刷新或自动轮询后可见；目前不发送工单回复邮件通知。SMTP 用于注册验证码。
- 旧工单保留，因没有注册用户归属，仅管理员可见。旧聊天、规划和模型配置仍属于管理员原有工作区。普通账号的聊天、研究、任务、日历、集成凭证、模型配置和执行检查点保存在各自 `.data/users/<账号ID>/` 下。普通账号需在自己的设置添加模型，不继承管理员的密钥。账号与工单继续共用主数据库，以便管理员处理。
- 注册成功和验证码发送成功使用绿色提示框；失败提示仍使用错误样式。

## 桌面端内嵌人机验证

按用户要求，登录和注册页直接显示 Turnstile，不打开系统浏览器。桌面使用实际 Chromium/操作系统版本的统一浏览器标识，在应用初始化时一次设置，不在验证过程中改变；保留 Cookie 和本地存储，仅向本机工作区内的 `https://challenges.cloudflare.com` 验证框授予存储访问权限。摄像头、麦克风等权限仍拒绝。没有修改验证码结果或绕过后端 Siteverify。

新版位于 `release-ui-v4/win-unpacked`。先从托盘选择「退出 Sakuya（停止本地服务）」，再使用根目录快捷方式打开。启动使用新的页面 URL，服务端 HTML 返回 `Cache-Control: no-store`，避免继续显示上一版页面。仍显示旧内容时可按 Ctrl+Shift+R。

Cloudflare 对嵌入式浏览器的支持有限，这些兼容性调整不代表已经证明真实挑战通过。若依然出现 600010，应继续记录真实运行结果，不能把模拟测试或改用外部浏览器视为内嵌验证修复完成。

之前的浏览器验证接口为兼容已发起的短期请求暂时保留；当前登录/注册 UI 没有调用入口。

参考：[Cloudflare WebView 接入要求](https://developers.cloudflare.com/turnstile/get-started/mobile-implementation/)、[浏览器支持范围](https://developers.cloudflare.com/cloudflare-challenges/reference/supported-browsers/)。

## 工作模式

界面统一为工作模式。工作首页显示「今天想做些什么？」；鼠标移动到右侧竖线、键盘聚焦或点击后，显示任务清单、日历、深度研究及 Issue 诊断。

选择功能后，桌面宽屏左边聊天、右边功能；关闭功能区域返回工作首页，草稿保留。窄屏采用上下布局。项目创建、编辑和导航已移除，旧记录不会被删除；诊断表单可直接填写 GitHub 仓库。知识库入口、资料添加入口和报告存入入口暂时隐藏，已有资料继续保存。

## 模型供应商

设置 → 填写供应商名称、API 根地址及 Key →「添加并加载模型」→ 选择返回的模型或手动输入模型 ID →「添加到模型列表」。可添加多个供应商；相同模型名称可以分别关联不同供应商。

当前支持 **Chat Completions 兼容协议**，不是原生 Anthropic Messages 等其他协议。自动发现调用供应商的 `GET /models`。不支持发现的供应商可手动输入 ID。管理员原有密钥保存在本机 `.data/provider.json`，普通账号密钥保存在各自 `.data/users/<账号ID>/provider.json`；编辑时留空保留密钥，修改根地址时必须重新输入，避免旧密钥被发送到新地址。

聊天框按设置中的模型列表切换。可将任一模型设为默认，删除默认模型后自动选择剩余模型。原单供应商配置会显示为「原有供应商」，添加新供应商时保留旧密钥。

仅对明确支持 `reasoning_effort` 的模型勾选「支持思考强度」，聊天框滑条对应「默认 / 低 / 中 / 高」。默认不发送该参数；其余发送 `low / medium / high`。不支持的模型禁用滑条，不会静默忽略用户选择。具体支持范围需要查阅供应商说明。

每个真实任务持久化所选供应商 ID、模型名与思考强度，不在任务记录中保存 Key。更改默认模型不会影响已排队的任务；删除任务所需供应商会让该任务明确失败。普通聊天、启用规划工具的聊天，以及聊天框发起的研究/诊断都使用该选择。

## 验证边界

自动测试使用独立数据目录和测试账号：API 覆盖密码、验证码有效期/次数、登录限流、会话注销/过期、对象权限和内部备注过滤；模型适配器使用受控 HTTP 响应验证供应商路由与思考参数。浏览器测试使用测试数据库会话，覆盖界面及真实本地 API，不绕过生产代码的鉴权。

真实 Turnstile、SMTP 投递和真实模型推理需要用户的服务配置。外部服务的模拟测试不能替代真实账号联调。

参考：[Turnstile 服务端校验](https://developers.cloudflare.com/turnstile/get-started/server-side-validation/)、[Turnstile 前端显式渲染](https://developers.cloudflare.com/turnstile/get-started/client-side-rendering/)。
